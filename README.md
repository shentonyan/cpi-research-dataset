## 理论框架：从 PI 到 CPI

本节概括 Physical Internet（PI）与 Cyber-Physical Internet（CPI）的理论关系，为本库的检索、筛选和精读提供工作框架。它不是新的正式定义，也不意味着CPI已有统一的行业标准或大规模部署。PI/CPI的中文译名在不同来源中并不完全一致；本库按研究对象和原文术语识别，不仅按中文名称归类。

### 1. PI：开放互联的实体物流网络

PI借用数字互联网的互联思想，研究如何让不同主体运营的物流资源与服务能够跨组织协同。其对象是现实中的货物、标准化载运单元、仓储与转运节点、运输通道和物流服务；互操作依赖封装/接口/流程等标准，以及网络协作和运营规则。概念上的目标是让货物能够在开放的物流网络中从起点到达目的地，而不必由单一企业拥有整个运输链。[Pan 等（2017）](https://doi.org/10.1080/00207543.2017.1302620) 将PI置于互联物流服务的研究脉络中；[Dong 与 Franklin（2021）](https://doi.org/10.1111/jbl.12253)进一步以网络模型讨论其可达性与运营优化。

PI与数字互联网的类比有明确边界。数据包可复制、缓存或重传；实物有尺寸、重量、装卸要求、库存位置、运输时间和不可忽略的边际成本。不同货物也并非都能装入同一种标准载具。因此，“像发送数据包一样发送货物”是设计愿景，不表示物流可直接套用TCP/IP或最短路算法。PI至少包含两个不同问题：**可达性**（网络中是否存在可行路径和服务链）与**优化性**（在容量、时窗、货物属性和参与方约束下，如何权衡成本、时间、排放、可靠性等目标）。路径可达不等于服务可行，更不等于整体最优。[Dong 与 Franklin（2021）](https://doi.org/10.1111/jbl.12253)

### 2. CPI：将数字表征和决策闭环接入 PI

本库以 [Wu 等（2025）的CPI系统综述与基础模型](https://doi.org/10.1016/j.tre.2025.104051) 作为当前的核心理论参照。该文指出，PI虽包含物理、数字与运营互联，但数字空间如何影响PI仍需进一步说明；作者据此提出CPI基础模型，把实体物流网络中的对象、数字表征、协议、寻址、路由和执行机制组织到分层架构中。按此框架，CPI的研究问题不只是“物流资源是否互联”，还包括：实体状态如何被数字化表示和更新；异构节点如何交换状态与请求；网络如何据此安排、路由和执行货运；执行结果如何反馈并支持后续决策。

该论文提出的五层结构自上而下为：

| 层 | 在该CPI模型中的主要职责 | 精读时需核对 |
|---|---|---|
| 应用层（Application） | 解释发送/接收请求，按请求条件管理和匹配待运输单元 | 请求包含哪些服务条件？谁发起、确认并承担责任？ |
| 传输层（Transport） | 为端到端运输建立逻辑连接；借助实体数字表征等机制检查连接/可达性并处理端口 | “可靠”具体指何种服务保证？仿真检查能否代表真实运力承诺？ |
| 网络层（Network） | 维护网络状态与路由信息，并作跨节点转发决策 | 路由是否同时考虑容量、时窗、拥堵、转运和多目标成本？ |
| 链路层（Link） | 处理相邻节点间的交接与本地寻址/转发信息 | 接口、地址映射、交接责任和异常处理如何定义？ |
| 基础设施层（Infrastructure） | 承接装卸、存储、转运等现实操作，使数字决策能够由物理资源执行 | 设备、空间、人员与操作时长是否进入可行性约束？ |

五层结构的理论作用是分解职责、约定层间接口，并让数字决策与物理操作相衔接；它是[该文提出的CPI模型](https://doi.org/10.1016/j.tre.2025.104051)，不是已被普遍采纳的标准。层次名称也不应与OSI/TCP-IP逐层等同：物流层需要处理实物装卸、容量、时间和服务承诺，这些约束不能由数字通信协议自动解决。不同研究提出的层数、层名和职责可能不同，应按原文编码，不能事后强行映射成同一架构。

### 3. 概念边界与可检验机制

- **IoT不是PI或CPI的同义词。** IoT通常强调物理对象的感知、连接和数据交换；PI关注开放互联的实体物流网络及物流服务；CPI则在相关PI问题上进一步研究数字表征、协议和网络决策如何与物理物流协同。IoT可以为PI/CPI提供数据与连接能力，但仅部署传感器或追踪系统，并不能证明形成了PI/CPI。
- **数字孪生不是CPI本身。** 数字孪生可用于表征对象或状态；只有当这类表征参与跨主体互操作、网络服务/决策，并与实际执行形成可说明的连接时，才构成更直接的CPI研究证据。仅在背景中提及数字孪生不足以归为CPI核心。
- **协作、激励与治理是跨层条件。** 信息共享、定价、隐私、信任、责任和收益分配决定开放网络是否可参与、可持续，但它们不是五层模型中另一个已定义的协议层。研究需明确参与方、信息结构、规则和可验证性质。
- **“效率、韧性、可持续性提升”是待检验结果，不是概念定义。** 需说明对照基线、系统边界、需求与容量假设、服务质量和排放口径，并区分理论分析、仿真、试点与真实运营证据。项目愿景或新闻报道不能单独证明效果。

据此，本库把CPI研究工作性地理解为：**研究数字表征与互操作机制如何改变开放物流网络中的服务、配置或执行，并说明其与现实物理约束的连接。** 这句话是本库的筛选和阅读框架，不取代论文作者定义。候选编码维度与网页来源局限见[PI/CPI网页线索与编码框架](docs/web-source-synthesis.zh-CN.md)；实际筛选边界见[方法与覆盖缺口](docs/methodology.zh-CN.md)。

## 本地重建与检索

需要 Python 3.10+。从仓库根目录运行：

```text
python -m pip install -r requirements.txt
python scripts/build_map.py
python scripts/finalize.py
python scripts/validate_public.py
python scripts/search.py "routing AND carbon" --tier core_cpi
```

已发布书目与地图可直接使用。完整重跑筛选需要本地原始输入；需要扩展检索时，运行采集脚本后再执行 `build.py`。原始缓存和下载的 PDF 写入忽略目录，`build.py` 在公开导出前移除原始摘要。不要直接上传采集目录；公开包使用 `scripts/package_public.py`。

## 研究纪律与私有性
