# PDF 原文与写作材料的本地工作方式

先阅读 [项目声明](../DISCLAIMER.md)。本说明提供文件组织方式，不替代具体文献、获取渠道、订阅及适用法律的使用条件。

## 本地目录

在仓库根目录建立 `local_only/`，可在其下分别放 `pdf/`、`text/`、`notes/` 和 `manuscripts/`。该目录、`library/`、`private/`、原始采集缓存和任意 PDF 扩展名均由 `.gitignore` 默认排除。

从有权使用的出版社、机构库、图书馆或作者渠道获取原文后，将文件放入 `local_only/pdf/`；提取文本保存在 `local_only/text/`。阅读笔记与写作草稿也可保存在 `local_only/` 内。不要把原文或草稿直接放入 GitHub Issues、Releases 或网站附件。

建议为每份本地文件记录：DOI、题名、作者、文章版本、来源 URL、获取时间、文件 SHA-256、适用许可/订阅或其他获取依据，以及阅读与引用位置。无法确认的字段标为待核，不把能下载视为获得再分发许可。

## 分析与写作

本地工具可以帮助检索、提取公式、比较模型、标注文献证据。在许可与适用法律允许范围内开展分析；将原文上传给第三方模型、共享存储或云服务是另一项使用行为，需另行核对条件。

形成写作内容时，区分论文原话、你的转述、自己的推导及 AI 辅助内容。回到原文检查引用、数据、图表、页码和版本；不要依赖自动生成的引文或把文字改写当成免除署名和许可义务。

## 发布之前

运行 `python scripts/validate_public.py` 检查公开版本；用 `python scripts/package_public.py 输出压缩包路径` 生成只包含 Git 跟踪文件的公开包。`.gitignore` 不会停止已经跟踪的文件或强制添加，检查也不能代替许可判断。

本项目的 PDF 下载尝试如成功，仍只写入被忽略的 `library/pdf/` 与 `library/text/`。下载器不默认公开其结果，也不将不明许可的可访问文件视为授权原文。
